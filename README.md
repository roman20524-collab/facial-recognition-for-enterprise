# Система пропусков: сервер, камера и администратор

Учебный проект для Windows, Python 3.11 или 3.12. Модели YuNet и SFace включены.

## Первый запуск

Распакуйте архив. Откройте папку access_system в VS Code. В терминале:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python setup_config.py
.venv\Scripts\python server.py
```

Если установлен Python 3.11, замените `-3.12` на `-3.11`.
Команда setup_config.py создаёт .env и два разных случайных ключа.
Повторный запуск не меняет существующие настройки.

Второй терминал в той же папке:

```powershell
.venv\Scripts\python admin.py
```

Третий терминал:

```powershell
.venv\Scripts\python camera.py
```

Если нужна другая камера: `camera.py --input 1`.
Проверка фотографии: `camera.py --input "C:\Фото\Роман.jpg"`.
Работает и прежняя команда `main.py` — она запускает камеру.
Закрытие окна камеры: английская Q.

## Работа администратора

1. Введите имя. Имена могут совпадать: у каждой записи собственный ID.
2. Заполните почту, если человеку нужен QR.
3. Выберите чёткое фото, на котором ровно один человек, и нажмите «Добавить».
4. Если нужен второй фактор, поставьте «Для входа обязательно лицо + QR» до добавления.
5. Выберите человека в таблице и нажмите «Отправить QR на почту».
6. Чтобы удалить человека, выберите его и нажмите «Удалить выбранного».
   Его QR также удалятся. Журнал останется.
7. «Обновить» загружает людей и последние 200 проверок.

Старые фотографии не добавляются автоматически: внесите людей через админку.
Новое фото должно изображать того человека, чьё имя вы вводите. Переименование
файла с фотографией Лехмана не превращает его в фотографию другого человека.
Для замены фото или настроек удалите запись и добавьте её заново.

## Как работает доступ

Камера каждые три секунды отправляет кадр серверу и ждёт ответа в фоновом потоке.
На кадре должен быть один человек. Несколько лиц приводят к отказу; проверяйте
людей по очереди. Сервер находит лицо, выравнивает его и вычисляет признаки SFace.
Затем сравнивает признаки с реестром SQLite. Совпадение имени не влияет на поиск.

При недостаточном сходстве или слишком близких результатах двух людей возвращается
Unknown и «Вход запрещён». При совпадении — имя и «Вход разрешён».
Если установлен обязательный QR, дополнительно требуется действующий код именно
этого человека. QR без распознанного лица не разрешает вход.

Покажите QR рядом с лицом; камера запоминает считанный код на 5 секунд, чтобы
можно было показать сначала телефон, затем лицо. Несовпадающий или просроченный
QR при проверке вызывает отказ. Без обязательного QR достаточно лица.

Каждая выдача создаёт новый случайный 256-битный токен; в SQLite хранится его SHA-256,
с уникальным ключом. Практически вероятность повторения пренебрежимо мала.
QR многократный и действует строго до ближайших 00:00 по TIMEZONE=Asia/Qyzylorda.
Все выданные за день коды действуют до полуночи; новая выдача не отменяет предыдущую.
При ошибке отправки почты новый код отзывается, интерфейс показывает ошибку.

На каждом ответе есть имя, allowed, status, дата, время с часовым поясом,
причина и score. Score — сходство признаков, а не процент уверенности.
Нет ответа сервера — вход запрещён. Приложение показывает решение,
но физическим замком или турникетом пока не управляет.

## Настройка почты в .env

Пример для SMTP-сервера вашего почтового провайдера:

```ini
SMTP_HOST=smtp.example.com
SMTP_PORT=465
SMTP_SSL=1
SMTP_USER=your-address@example.com
SMTP_PASSWORD=your-app-password
SMTP_FROM=your-address@example.com
```

Это пример адреса, укажите реальные значения своего провайдера.
Для STARTTLS используйте порт 587 и SMTP_SSL=0.
Часто нужен пароль приложения, а не пароль от входа в почту.
После изменения .env перезапустите сервер. Без SMTP распознавание работает,
но выдача QR показывает ошибку — фиктивной успешной отправки нет.

## Telegram для директора

В .env заполните TELEGRAM_TOKEN и TELEGRAM_CHAT_ID директора.
Директор должен сначала открыть бота и нажать «Старт».
CHAT_ID — числовой идентификатор чата получателя, а не имя распознаваемого человека.
Сервер отправляет фотографии проверок с именем и результатом, в том числе Unknown.
Для одинакового имени и результата отправка ограничена одним сообщением в минуту.
Ошибки Telegram не меняют решение о доступе.

В исходном архиве был открытый токен бота. Он не перенесён в новый проект:
отзовите его через BotFather и укажите новый в .env.

## Почему старый вариант работал неправильно

- Словарь users содержал только Лехмана. Для другого распознанного имени возникал
  KeyError, а поле user ошибочно использовалось как адрес получателя Telegram.
- Были перепутаны обязанности: сравнение лиц сразу отправляло сообщения боту.
- Вызов feature получал два аргумента; исправлен на feature(alignCrop(...)).
- Порог 0.363 мог пропускать ложные совпадения; теперь стартовое значение 0.50
  и дополнительно проверяется отрыв от второго результата.
- Файл модели SFace в присланном архиве повреждён (бинарные данные содержали
  следы текстового декодирования). Он заменён исходным ONNX из OpenCV Zoo.

Порог не гарантирует точность: проверьте на нескольких разных людях при вашем
освещении. FACE_THRESHOLD повышается для более строгой проверки. FACE_MARGIN
задаёт минимальный отрыв от второго кандидата. При неуверенности система отказывает.

## Файлы и принципы

- server.py — API, авторизация ключами, SQLite, журнал, правила доступа и QR.
- recognition.py — обнаружение лица и сравнение признаков; никаких Telegram-вызовов.
- camera.py — захват видео, чтение QR и запросы к API; русские подписи через Pillow.
- admin.py — отдельная настольная админка Tkinter; запросы не блокируют окно.
- services.py — создание PNG QR, SMTP, Telegram.
- config.py — единые настройки и пути относительно проекта.
- setup_config.py — создание локальных секретов.
- data/access.sqlite3 — создаётся при запуске. Содержит реестр и журнал.
- models/ — две ONNX-модели.

Ключ администратора не подходит к маршруту камеры и наоборот. Сервер по умолчанию
слушает только 127.0.0.1. Для размещения на разных компьютерах потребуются
HTTPS и отдельная настройка размещения; текущий запуск рассчитан на один ПК.
Не публикуйте .env и data в GitHub.

Это учебная система без проверки живого человека: фотография перед камерой может
пройти распознавание. Для реального контроля доступа нужны liveness и испытания
на ложные допуски; требование QR само по себе эту проблему не устраняет.

## API

Заголовок X-API-Key: ADMIN_KEY для админских маршрутов, CAMERA_KEY для проверки.

| Метод | URL | Назначение |
|---|---|---|
| GET | /health | Проверка доступности |
| GET | /api/people | Список людей |
| POST | /api/people | multipart: name, email, require_qr (0/1), photo |
| DELETE | /api/people/<id> | Удаление человека и его QR |
| POST | /api/people/<id>/qr | Новый QR и письмо |
| GET | /api/events | Последние 200 записей |
| POST | /api/check | multipart: photo, qr (необязательно) |

Проверка правил API без внешних сервисов:

```powershell
.venv\Scripts\python -m unittest -v
```

Тесты используют отдельную временную БД и подменяют распознавание, почту и Telegram.
Они проверяют права, Unknown, удаление, срок QR, чужой QR и отзыв при ошибке почты.
Они не подтверждают качество распознавания на реальных людях или доставку сообщений.

Модели: https://github.com/opencv/opencv_zoo
SFace: https://github.com/opencv/opencv_zoo/tree/main/models/face_recognition_sface
YuNet: https://github.com/opencv/opencv_zoo/tree/main/models/face_detection_yunet
Условия лицензии моделей приведены рядом с ними.
